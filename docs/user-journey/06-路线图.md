# 06 · 路线图：已定义未实战的能力与边界

> 使用者之旅 · 第 6 章（末章）。诚实清单：什么今天能用，什么写在 spec 里但还没人真的跑过。

## Jira / Confluence 连接器：spec 完整，尚未实战

spec 和 SKILL.md 对 Jira/Confluence 连接器有**完整定义**(§3):

- Server/DC 实例，PAT 认证（PAT 存环境变量，kb.json 只存变量名——密钥永不上盘）;
- 四种选择器：页面 URL / Jira issue key / JQL / CQL，可自动嗅探；
- 增量拉取、两击删除规则、附件 hash 去重、XHTML→Markdown 转换（未知宏降级为 `[macro: name]` 占位，绝不静默丢弃）;
- Cloud 实例**不支持**(v1 只有 Server/DC)。

**但是**：截至 v1.1，还没有任何真实 KB 用它们拉过一篇文档（fixtures 里的 `raw/jira/`、`raw/confluence/` 是手工构造的教具）。如果你要成为第一个实战用户：

1. 预期会遇到粗糙边缘——遇到了请记录，这正是教程和 spec 需要的反馈；
2. 排错速查（init 引导同款）:401 = PAT 过期重发；403 = PAT 权限不够；全部 404 = base_url 指错（要指 Server/DC 根，不是 Cloud)；超时 = 网络/VPN 问题，不是凭证问题；
3. Zephyr Scale 测试步骤拉取明确推迟到连接器二期。

## 明确的边界（v1 不做什么)

| 边界 | 说明 |
|---|---|
| 单 KB | 多 KB 只有 `--kb` 参数这个逃生口，没有跨 KB 检索 |
| ≤500 页 | 检索协议的设计容量；超出后 rebuild-index 自动生成 `wiki/topics.md`(Tier 0.5 topic 索引，v1.2 起）配合分节读索引 |
| 无搜索引擎 | 检索纯靠 agent 迭代（Grep/Glob/Read);KB 大到一定规模后召回率受宿主能力影响 |
| 蒸馏转录靠 agent | 附录保真 = validate 一致性校验 + agent 自律，不是代码机械保证 |
| 降级模式体验打折 | 无 Node 时全流程可手动跑，但自动批准关闭（全部进候选）、graph 视图跳过 |

## 演进方式

- skill 语义化版本 + `CHANGELOG.md`;KB 契约只增量兼容演进，破坏性变更必带迁移说明；
- `kb.json` 的 `contract_version` 是运行检查点：skill 比 KB 新时，脚本退出码 65 并给迁移指引；
- 升级 = 覆盖整个 skill 目录（所有个人化数据都在 KB 侧，覆盖安全）+ `install.mjs update` 重投影。

v1.0 → v1.1 的演进故事（截断 → 折叠）本身就是"设计如何被真实使用证据驱动"的好案例，见 [dev-journey 03 · fold 机制](../dev-journey/03-fold机制.md)。
