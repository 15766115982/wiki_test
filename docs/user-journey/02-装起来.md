# 02 · 装起来

> 使用者之旅 · 第 2 章。目标：装好的 skill + 初始化好的 KB + 配好的环境变量。约 10 分钟。

## 前置条件

| 条件 | 检查方法 | 说明 |
|---|---|---|
| Claude Code(或 Copilot) | — | skill 运行的宿主环境 |
| Node.js ≥ 20 | `node --version` | 四个增强脚本需要。**没有也能用**(SKILL.md 每章都有手动降级路径），但自动校验、自动批准会关闭，体验打折 |
| git | `git --version` | KB 必须是 git 仓库（历史追溯、手工改动检测都依赖它） |

## 第一步：安装 skill

skill 的真实位置是 `~/.claude/skills/llm-wiki/`(Claude Code 原生读取）。如果你还要给 Copilot 或中性宿主用，运行安装器把它投影过去：

```bash
node <skill目录>/scripts/install.mjs            # 首次安装
node <skill目录>/scripts/install.mjs update     # 升级后同步
```

Windows 优先建 junction,POSIX 优先建 symlink；失败则退化为整目录拷贝（带版本戳）。输出里 `mode: junction | symlink | copy` 告诉你用了哪种方式。

装完后新开一个会话，说一句"**初始化 KB**"，看 skill 是否被触发——能触发即安装成功。

## 第二步：初始化 KB

在会话里说一句：

> **初始化 KB**

agent 会引导你走完五步（它每步都会先问你再动手）。这里把你会被问到的事先说清楚：

1. **KB 放哪？** 默认建议 `~/kb`。这是个独立全局目录，**故意不放进任何代码仓库**——换项目工作时知识不丢。
2. **创建目录树**:`raw/`（证据层）、`wiki/`（策展层）、`.kb/`（机器衍生品，gitignore)、`kb.json`、`GOVERNANCE.md`、`log.md`。
3. **`git init`**——必须是 git 仓库。
4. **设置环境变量**(Windows 示例，新终端生效）:

   ```
   setx LLM_WIKI_KB "C:\Users\<你>\kb"
   ```

   之后每个会话自动发现 KB，零废话。多 KB 是 v1 的明确边界——`--kb` 参数是内置的逃生口。

5. **写 kb.json**。最小可用配置（不用 Jira/Confluence 时）:

   ```json
   {
     "contract_version": 1,
     "language": "zh",
     "connectors": {},
     "governance": { "max_clusters_per_run": 10, "max_sources_per_cluster": 1, "max_chars_per_source": 2500 }
   }
   ```

   `language: zh` 表示 wiki 页面用中文写；raw 层永远保留来源原文语言。三个 governance 值是默认值可省略；注意 `max_sources_per_cluster` 是**每折折入几篇源**（默认 1，推荐保持），不是覆盖上限。

> **如果你拿到了别人 git clone 给你的 KB**：跳过建目录，只需确认 `kb.json` 存在、设置 `LLM_WIKI_KB` 即可。

## 第三步：验证

说一句：

> **蒸馏**

然后随便聊几句，再说"把刚才的存进 KB"。如果 `raw/chat/` 下出现了一篇 `conv-xxxxxxxxxxxx.md`，链路就通了——这是唯一不需要任何外部账号的验证路径。

## 动手试试 🔧

不想动真 KB？仓库里带了一个教具 KB，先跑个体检：

```bash
cd D:\claude\kb-skill
node llm-wiki/scripts/govern.mjs --kb llm-wiki/fixtures/kb plan
```

这个 fixtures KB 是一个虚构的"支付"领域示例：4 篇 raw（支付库表设计、回调重试讨论……）、已批准的 wiki 页面、一篇待裁决的候选 `wiki/concepts/retry-policy.candidate.md`。`plan` 输出的六个列表（待消化/异常/错误/待裁决队列/健康清单/被抑制）就是第 4 章要讲的治理入口视图。
