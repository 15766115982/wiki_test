# 05 · 读出来：站点与检索

> 使用者之旅 · 第 5 章。知识进了 KB，怎么舒服地拿出来用。

## 生成站点：双击即开的本地 wiki

> **生成站点**

脚本：`node scripts/render.mjs --kb <path> site` → 产出 `.kb/site/index.html`。**单文件、零依赖、零守护进程**——数据 JSON 直接嵌在 HTML 里，双击就能看，发给别人也能看。四个视图：

| 视图 | 看什么 |
|---|---|
| **browse** | 按页型浏览（可折叠分组），按 issue_type/tag/来源过滤；每页正文 + frontmatter + 溯源链 |
| **graph** | wikilink 关系图：canvas 实时力导向模拟，滚轮缩放/拖拽/悬停提示；500 节点内流畅。枢纽页（synthesis/concept/entity）显示标签，source 页悬停显示——不会糊成一片字 |
| **history** | 裁决时间线：谁、何时、对哪页、做了什么、理由是什么（来自 decisions.jsonl + log.md) |
| **overview** | 页型统计、run 历史、孤儿页/悬空链接健康度 |

安全设计：raw 正文、review_note、你的裁决理由都是不可信输入，渲染前全部实体转义；链接 href 白名单；不跑行内 HTML——所以这份单文件 HTML 可以安心双击。

## 检索：问就完了

普通问题直接问，不用口令。检索协议的六个要点（对使用者而言你只需感知到这些行为）:

1. **索引先行**——先读 `wiki/index.md` 建全局地图；
2. **多路召回**——全文搜索 + 文件名匹配，查询词自动做同义词和中英交叉扩展；**禁止**编造"假想文档"当查询（禁 HyDE)，只允许从已命中页提取新关键词再查（CSQE);
3. **图扩展**——命中页沿 wikilink 和来源链各扩一跳（synthesis 命中会拉进它的 sources 交叉验证）;
4. **迭代加深**——按标题分节读，最多 3 轮，不整篇吞；
5. **引用纪律**——只从读过的页作答，每条结论带 `[[wikilink]]`；关键结论带 ≤25 词原文引用，**机器校验是原文子串**才输出；零命中直说"KB 中没有此内容";
6. **检索说明**——答案末尾一行账目：查了哪些渠道、读了哪几页。

例：

> 支付回调重试几次？

> Jira 任务说 8 次（[[pay-callback-retry]]);Confluence 设计文档说 5 次（[[pay-table-design-v3]]);synthesis [[payment]] 记录了裁决后的结论……
> *检索说明： queried [full-text: "重试","retry"; index]; read [[payment]] (+2 via:provenance)*

注意这个例子里系统**没有掩盖矛盾**——两个来源不一致时，把两边都摆出来并指向裁决记录，正是 KB 的价值。

## 深研：强制拉满迭代

> **深研 \<问题\>**

普通提问是"单档自适应"(agent 按问题复杂度自己选轮数）；加上"深研"二字 = 强制最大多轮迭代，适合"把 KB 里关于 X 的一切都挖出来"这类问题。

## 看不见的东西同样重要

检索**只看 approved 页面**，而且是结构性保证：候选文件（`*.candidate.md`）和 `archive/` 在枚举时就被 glob 机械排除，不靠 agent 自觉。含义：

- 候选里的内容（可能正确但未经你确认）**不会**混进答案；
- 被驳回/归档的旧说法**不会**复活；
- 如果你发现答案漏了什么，先想想：那篇内容是不是还躺在候选队列里等你 approve?

规模上限：协议按 ≤500 页设计。超出后 rebuild-index 会自动多生成一份 `wiki/topics.md`(Tier 0.5 二级索引，topic → 页映射，v1.2 起落地），检索先读它定位 topic，再按页型分节读 index.md；千页量级建议显式「深研」或先用 frontmatter 过滤缩候选。
