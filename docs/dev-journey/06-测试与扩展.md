# 06 · 测试与扩展

> 开发者之旅 · 第 6 章（末章）。改代码后怎么验证，新能力往哪里加。

## 测试地图

测试在仓库根的 `tests/`（注意：不在 skill 目录里——skill 目录是交付物，测试是开发产物），Node 内置 test runner，零依赖：

```bash
node --test tests/
```

| 文件 | 覆盖 | 对应契约 |
|---|---|---|
| `contract.test.mjs` | KB 契约校验：frontmatter、slug、状态白名单 | spec §2 |
| `validate.test.mjs` | validate 两套检查集（govern/distill)、重融护栏 | spec §2.2/§5 |
| `acquire.test.mjs` | 选择器嗅探、增量、两击删除、OpenWiki 扁平化 | spec §3 |
| `govern.test.mjs` | sweep/plan 六列/rebuild-index/record-decision、run 锁 | spec §4 |
| `govern-fold.test.mjs` | fold 执行器(串行闸门/断链恢复/续跑跳过)、Tier 0.5 topic 索引 | spec §4.1/§7 |
| `render.test.mjs` | 裁决报告与站点的 HTML 安全（转义、href 白名单） | spec §6 |
| `install.test.mjs` | 投影模式、版本戳、拒绝覆盖外来目录 | spec §9 |
| `e2e.test.mjs` | **全链路**:fixtures → acquire → govern run → 裁决 → render | spec §10 |
| `helpers.mjs` | 测试基建：`runScript`、`git`、临时 KB 构造、FIXTURES 定位 | — |

e2e 的写法值得读：文件头注释明确记录了**降级路径与脚本路径的三个文档化差异**(content_hash: "manual" / 降级禁自动批准 / agent 代提交）——机器只校验脚本路径的产物，降级路径的承诺是 SKILL.md 的文档义务。这种"什么能机测、什么只能靠文档诚实"的划分本身就是设计。

## 扩展指南

### 加一个新 connector(如 Zephyr Scale、GitLab wiki)

1. `spec` §3 加一节连接器规范：选择器形式、认证、增量语义、删除语义（两击还是直接删？)、附件策略；
2. `scripts/acquire.mjs` 加实现——遵守共同约定：stdout JSON、退出码、detect-first、commit 纪律、错误消息精确无密钥；
3. raw frontmatter 的 `source` 白名单加新值（spec §2.2 + validate.mjs);
4. fixtures 加样本，`acquire.test.mjs` 加用例；
5. SKILL.md ch.3 加 CLI 形式和手动降级路径（**用户粘贴内容时 agent 怎么手工归一化**——这是最容易被忘的一步）。

### 加/改一个 prompt 模板

1. `prompts/` 下新建或修改，保持"结构化输出契约"传统（如 semantic-check 的 `{conflicts}`/`{no_conflict}`)——**无结构化输出 = 未执行**是 fail-closed 的支柱；
2. SKILL.md 对应步骤点名引用文件名；
3. spec §4.3 模板清单同步；
4. 没有直接单测——e2e 是兜底。改 prompt 后至少手动跑一遍完整治理验证。

### 改契约（字段/规则）

最高纪律区：spec 双语两版同步 → 评估 `contract_version`(v1.1 的"语义变、键名不变、不 bump"是参照案例）→ SKILL.md → validate.mjs → 模板 → CHANGELOG（破坏性变更必须带迁移说明）→ 本教程目录（见下）。

## 文档同步约定

本教程（`docs/`）不是契约权威——spec 和 SKILL.md 才是。项目根的 `CONTEXT.md` 里有一条约定：改 spec / SKILL.md / CHANGELOG 时必须检查 `docs/` 是否受影响。如果你在 Claude 会话里改这些东西，agent 会主动提醒你；如果你手工改，请自觉执行。

## 收尾：开发者之旅的三句话总结

1. **SKILL.md 是规范，脚本是增强，prompts 是判断**——改东西先想清楚动的是哪一层；
2. **一切正确性尽量下沉为结构**(glob 排除、sidecar、白名单、原子 rename)，提示词叮嘱是最后手段；
3. **人审是最贵资源**——每个设计决策都值得问：这会产生"只需确认"的候选噪音吗？
