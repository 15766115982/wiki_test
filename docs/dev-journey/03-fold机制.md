# 03 · fold 机制：v1.1 为什么用折叠取代截断

> 开发者之旅 · 第 3 章。这是理解当前代码形态的钥匙——v1.1(2026-08-13）重写了 synthesis 的构建方式。故事见 `CHANGELOG.md [1.1.0]`，契约见 spec §4.1 steps 3–4，执行见 SKILL.md ch.4 step 4。

## 问题：截断策略在第一次真实使用中崩了

v1.0 的设计：synthesis 一次性覆盖整个簇，但设了 ≤6 源的上限，装不下就截断，并在下一轮把"未覆盖 N 篇"列为强制候选。

第一次真实使用（Weft 项目，47 篇 openwiki raw）的证据：**9 个簇里 7 个撞了上限**，裁决队列被"N sources not covered"候选淹没。每个候选都要人看，但人能做的决定无非是"好，下轮继续"——**这不是判断，是确认噪音**。设计原则"自动化优先，只在必要时裁决"被自己的实现违反了。

## 解法：把"一次覆盖"改成"增量折叠"

核心想法来自版本控制：与其一次性写一篇大页面，不如**每次折入一个源，每折过闸门，页面是折叠链的累积结果**。

```
fold 1:  ∅ ──折入源 A──▶ 页面 v1 ──双闸门──▶ 落盘
fold 2:  页面 v1 ──折入源 B──▶ 页面 v2 ──双闸门──▶ 落盘
fold 3:  页面 v2 ──折入源 C──▶ 冲突!──▶ 断链:v2 保持,C 折进候选
```

### 每折的纪律（spec §4.1 step 4)

1. **先读当前页**——它是之前所有折叠的 merge base。**跳过这次读取就是契约违规**(agent 提示词层面强制）;
2. **按 `source_version` 升序读下一源**——旧说法先进，新说法后落。为什么升序？让冲突**恰好暴露在相撞的那一折**：如果新文档改口了，你会在折入它的那一折看到它和既有页面矛盾，而不是事后发现页面里有两种说法；
3. **union-merge**:`sources` 只并集，`created_at` 保留，正文重新融合时**优先把新源的结论作为带来源标签的追加**，而不是整体重写（下条的护栏机械检查这一点）;
4. **双闸门，每折必过**:
   - `validate.mjs --file`，含**重融护栏**(refusion-retention guardrail)：新页面若丢掉 base 的 wikilink/sources，或 >20% 关键事实行消失 → 校验失败；
   - `semantic-check.md`，必须输出结构化证据 `{conflicts:[…]}` 或 `{no_conflict:true}`——**没有结构化输出 = 没有检查 = 强制候选**。

### 断链与续跑

- **断链**：矛盾 / 护栏破损 / 无结构化证据 → 链停在这一折：最后好页保持，问题折落候选（review_note 首行 `conflict: <kind> | parties: <a> vs <b>`，机器可解析，render 的冲突块靠它），剩余源下轮续；
- **续跑靠结构，无游标文件**：页面 frontmatter 的 `sources:` 就是游标。`簇成员 − 页.sources` = 下轮的剩余工作。少一个状态文件，就少一个会和现实漂移的状态。

### 风险红线的相应修订

通过全部闸门的一折（①sources 只并 ②护栏过 ③明确 no_conflict）视同**纯追加** → 可自动批准。注意 `no_conflict` 从来不是单独放行理由：改写/删除即使语义检查无冲突也强制候选。

## 设计层面的三个收获（可迁移到别的项目)

1. **把人审从"流程的常态产物"中摘出去。** 截断策略让每个大簇必然产生人审；折叠策略让人审只在**真有矛盾**时出现。衡量自动化设计健康度的指标：每 run 产生的候选里，"需要判断"和"只需确认"的比例。
2. **批量上限换成增量批次，语义完全不同。** `max_sources_per_cluster` 从"这一簇最多覆盖几篇"（覆盖上限 → 必然截断）变成"每折折入几篇"（批大小 → 覆盖总是全量）。键名没改、kb.json 不 bump——兼容性靠"旧值在新语义下仍然合法"达成。
3. **进度编码进数据结构，而不是进度文件。** `sources:` 清单天然就是游标。当你想引入一个 `progress.json` 时，先问：现有结构里有没有一个字段已经在记录同样的事？

## 代码里的落点

- 折叠纪律的提示词载体：`prompts/draft-synthesis.md`(v1.1 fold-mode 重写）、`prompts/draft-concept.md`、`prompts/extract-entity.md`;
- 机械闸门：`scripts/validate.mjs`（重融护栏在 govern 检查集里）;
- 机械执行器：`govern fold`(v1.2 回收自 KB 侧的 fold-run.mjs)——agent 组好 folds.json（撰写即 semantic-check 的结构化证据），执行器严格串行落折、每折过 validate 闸门、断链恢复最后好页；断链候选仍由 agent 撰写（点名相撞源对需要判断）;
- 串行纪律：SKILL.md ch.4 step 3.10 明确子代理并行**只**适用于 source 页起草——非 source 页永不并行；
- 折叠顺序的语义：`source_version` 升序，见 spec §4.1。
