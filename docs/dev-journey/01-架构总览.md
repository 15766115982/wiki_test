# 01 · 架构总览

> 开发者之旅 · 第 1 章。给要改这个 skill 的人：先建立地图，再谈细节。建议先翻过 [user-journey 01](../user-journey/01-这是什么.md) 和 [04](../user-journey/04-日常循环.md) 建立使用者直觉。

## 最重要的架构事实：这不是一个程序，是一份给 agent 的 runbook

```
llm-wiki/
├── SKILL.md        ← 唯一规范路径:skill 被触发后,agent 照它执行一切(507 行)
├── prompts/        ← 9 个 prompt 模板,在 SKILL.md 各步骤按文件名引用
├── scripts/        ← 5 个 Node 零依赖单文件脚本,渐进增强,不是必需品
├── templates/      ← 页面骨架(4 类 wiki 页 + raw)+ 2 个 HTML 模板
└── fixtures/       ← 教具 KB + 上游仓库样本,测试和本教程共用
```

设计原则（SKILL.md §1，贯穿一切）:

1. **prompts first**——判断性工作全部由宿主 agent(LLM）执行；脚本是省力的机械部分；
2. **scripts as progressive enhancement**——没有 Node 环境，SKILL.md 每章有写到"agent 可照做粒度"的手动降级路径；
3. **fail-closed**——检查跑不了 = 检查不通过 → 进候选交人审；
4. **correctness by structure, not by discipline**——正确性靠目录结构/glob 排除/frontmatter 白名单机械保证，不靠"agent 记得不要做某事"。

第 4 条是这个项目的灵魂，读代码时用它当试金石：凡是看到"检索排除候选"靠的是 glob 模式而不是提示词叮嘱，看到"approved 页永不被候选覆盖"靠的是 sidecar 文件模型而不是警告——都是这条原则的落实。

## 数据流：一次治理 run 里各部件如何协同

```
raw/(证据)                    agent(判断)                  wiki/(结论)
   │                             │                            │
   │  govern.mjs plan ──────────▶│ 六列表格:pending/anomalies/│
   │   (机械扫描,纯 stdout JSON) │  errors/review_queue/      │
   │                             │  human_lists/suppressed    │
   │                             ▼                            │
   │  读 raw ──────────────────▶ 分类(classify-page.md)      │
   │                             起草(draft-source-page.md)  │
   │                             + prompts 注入 GOVERNANCE.md│
   │                             ▼                            │
   │  validate.mjs --file ◀───── 每篇草稿 fail-closed 校验    │
   │   (通过/拒绝,exit 0/1)     ▼                            │
   │                      语义检查(semantic-check.md)        │
   │                             必须输出结构化证据            │
   │                             ▼                            │
   │                      低风险 → record-decision 记录 ─────▶ approved 落盘
   │                      有风险 → 写 sidecar ──────────────▶ *.candidate.md
   │                             ▼                            │
   │  render.mjs report ────────▶ 裁决 HTML(人审)            │
   │  govern.mjs rebuild-index ─────────────────────────────▶ index.md 重建
```

脚本的共同工程约定（spec §1.2)：零依赖单文件 `.mjs`、stdout 恒为 JSON、退出码 `0/1/64/65`、错误消息精确可操作且绝不含密钥。**没有任何脚本被自动执行**——都是 agent 通过宿主终端能力调用的。

## 五个脚本的分工

| 脚本 | 干什么 | 不改它的情况下你要知道的 |
|---|---|---|
| `acquire.mjs` | Jira/Confluence/OpenWiki → raw/ | 最大的一只（连接器逻辑）；选择器嗅探、增量 detect、两击删除都在这 |
| `validate.mjs` | fail-closed 契约校验 | govern 模式和 distill 模式两套检查集；含重融护栏；`splitFrontmatter`/`serializeFrontmatter` 被测试直接 import |
| `govern.mjs` | sweep/plan/rebuild-index/record-decision | run 锁（`run.lock`,2h 自动回收）、六列计划表、决策记录 |
| `render.mjs` | 裁决报告 + 静态站点 | 全部动态内容实体转义；数据构建期嵌入，无运行时 fetch |
| `install.mjs` | 投影 skill 到 `~/.agents/skills/` | junction/symlink 优先，整目录拷贝兜底（版本戳防误覆盖） |

## 九个 prompt 模板：agent 的"思考框架"

`prompts/` 下的文件不是给人看的文档，是 SKILL.md 各步骤点名加载的工作指令：`classify-page`（分类）、`draft-source-page`/`draft-synthesis`/`draft-concept`/`extract-entity`（四类起草）、`semantic-check`（语义冲突检查，强制结构化输出）、`govern-decide`（用先例 few-shot 自动裁决重复情况）、`distill-chat`（蒸馏）、`query-rewrite`（检索改写，CSQE 规则的载体）。

`GOVERNANCE.md`(KB 侧，用户自写）在治理类 prompt 里以 `{{brief}}` 注入——这是用户不动 skill 代码就能定制治理行为的口子。

## 改代码的第一站

- 改**行为/流程** → 先改 `SKILL.md` + 对应 `prompts/`，再改 `spec`（双语两版），脚本最后；
- 改**契约（字段/规则）** → 先改 `spec/spec.zh-CN.md` + `spec.en.md`，评估 `contract_version` 是否 bump，再同步 SKILL.md、validate.mjs、模板；
- 改**任何上面两者** → 跑测试（见 [06 · 测试与扩展](06-测试与扩展.md))，更新 CHANGELOG。
